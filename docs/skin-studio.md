The native Inventory page uses an image grid for guns and knives. Search filters finish names; selecting a card edits the existing loadout entry, retaining wear and seed. The right panel contains a preview, paint ID, wear, seed, StatTrak, apply, and removal controls. Glove selection remains text-based because the supplied catalog has no glove images.

Images are read from `skins_images/output.jsonl` and `skins_images/images/<imageid>.png`. The mapping uses weapon and finish names, not paint IDs. Exterior suffixes and market prefixes are removed when matching; the existing skin database still supplies paint IDs. Missing files or unmatched finishes show a placeholder. The supplied mapping references 28 PNGs absent from the supplied images folder.

The build copies the library beside the DLL. Runtime searches there first, then `core/skins_images`, then the source directory for development. Catalog parsing and PNG decoding run asynchronously. Thumbnails are reduced to at most 320 pixels, uploaded on the render thread, and retained in a cache with a 96-entry target; eviction runs between frames so draw commands cannot reference freed textures. Renderer reset joins outstanding work and releases cached GPU resources.

Run `tests/run_feature_regressions.ps1` for catalog matching, Unicode decoding, missing-image handling, WIC decoding, D3D11 WARP upload/rendering, and resource reset checks. The fixture generates `tests/out/features/skin-studio.bmp` using the production menu and supplied images, with fixture paint IDs for preview purposes only. This does not validate appearance inside CS2.
