Silent-aim performance follow-up

The subtick hook previously waited for the settings mutex, which Present also holds through ESP and menu rendering. The hook now tries the mutex once. If another thread owns it, the original serializer runs unchanged and aim is skipped for that callback. This avoids waiting for a busy rendering pass; it can reduce aim updates during sustained contention.

Target snapshots retain their 8 ms expiry. Geometry is recalculated only after a snapshot refresh or a local eye-position change. Current source angles, FOV, range, and team/visibility settings still participate in each selection, and the selected entity's serial and health are checked before writes. Game-state reads use one snapshot inside the aim routine instead of repeated state locks and a module-loader lookup. History verification is diagnostic and now sampled at 4 Hz per callback thread, rather than reading history and flags for every write.

The native aim diagnostics show **Geometry updates** and **Busy-settings skips**. **Verified history samples** is a sample count, not the total number of writes.

Validation: the feature regression fixture exercises 64 distinct player pawns and 1,000 callbacks, checks cache refresh on movement/expiry/weapon changes, current-angle/FOV filtering, and rejects dead targets. The callback fixture holds the settings mutex on a separate thread while 1,000 serializers complete, verifying that every original is forwarded without an aim write. Both test runners pass. One local synthetic comparison measured 25.4 ms before and 16.7 ms after per 1,000 crowded-map aim callbacks; this excludes the actual engine serializer and is not an in-game FPS measurement.

Rebuild the DLL to use the changes. Live FPS and frame-time improvement remain unverified.

Additional performance pass: target snapshots now retain a compact list of living remote player slots. Geometry updates and callback selection iterate that list rather than all 64 slots; controller indices and selected-target validation are preserved. The 8 ms snapshot expiry remains unchanged. Server tick rate alone is not used to throttle client input callbacks.

The glove path now checks whether the current pawn, spawn, team, selected kit, and glove definition already match before traversing the paint-kit schema. Schema lookup and failed-build retries still run when a material update is needed. Feature regressions cover sparse and full target lists, staged skins, glove changes, restoration, and material retry behavior. These changes have not been profiled in a live ten-player match and do not establish the cause of the reported 60 FPS drop.

Ten-player slowdown/respawn follow-up: the serializer now restores the original source angles after the engine copies the aimed angles into history. Tick fields and serializer arguments remain untouched. Dead or replaced winners are removed from the current selection pass, allowing another candidate to win, and invalidate the next snapshot. Snapshot reuse now lasts 16 ms after scan completion; this approximates a 64 Hz refresh and can add up to 16 ms of target-position age. Spotted Check still requires the engine's local-player spotted bit, including after respawn; this is not a ray-traced visibility test. The invalid-history console messages and live 3 FPS report have not been reproduced or confirmed resolved.

Profile-driven memory-read pass: silent-aim evaluations opt into a per-thread, per-evaluation readable-region cache with exception-protected local memory copies. Cross-region reads retain the ReadProcessMemory fallback. Other features retain their previous read path. Target snapshots reuse the pawn handles already checked during controller enumeration, removing duplicate identity reads. The 16 ms snapshot window and winner identity/health checks remain unchanged. Tests cover inaccessible mappings, mappings protected after caching, initially guarded pages, and unchanged output on failure. The crowded fixture asserts zero ReadProcessMemory calls for 1,000 silent evaluations; live scan-time/FPS improvement must be checked against the supplied profile.

Profiler v2 adds nested self time, p50/p95/p99 histogram upper bounds, and callback-versus-skin attribution for memory and lookup timings. It distinguishes VirtualQuery, ReadProcessMemory, WriteProcessMemory, validated local reads, engine entity lookups, handle checks, controller enumeration, bone/eye reads, and final winner validation. Event counts distinguish menu, disabled, stopping, and busy-settings skips, successful writes, no-write evaluations, target-cache hits/misses, region-cache hits/misses/full, and invalid winners. Build timestamp and settings at capture request are included. Settings may change after the request; skip counters expose menu/disabled intervals. Memory-failure counts record selected failed operations, not a count of distinct invalid addresses. Detailed probes run only under captured parent scopes, without per-call logging. Profiling itself adds timing/atomic overhead; compare captures using the same diagnostic build. Completed scopes admitted before the deadline may finish afterward, so totals include their full duration. Copy results after the in-flight count reaches zero.

User-requested live-target mode: removed the timed silent-target snapshot and geometry reuse. Each evaluation builds a value-owned target set from current fields; add/remove hooks still maintain the entity registry and validate serial handles. The registry is lifecycle state, not a cache of health, visibility, bones, or aim angles. A one-time bootstrap and unavailable-hook fallback remain. Existing shot/kill-delay and target-lock settings remain intentional feature state. Regression tests pass with one scan/geometry calculation per evaluation. The synthetic 64-player/1,000-callback fixture took approximately 183 ms in this mode; removing reuse increases work and is not itself a performance optimization.
