# Dashboard and aim-loop review

- Replaced the menu shell with an overview dashboard, drawn navigation icons, session cards, quick settings, and exponential hover/page transitions. Existing feature pages remain accessible. Removed the unused Globals/Weapons buttons and the hard-coded VAC status claim.
- Use Segoe UI for the dashboard when available, with the existing font fallback. Load fonts during renderer initialization and clear pointers on renderer teardown. Cards now size to their content, instead of consuming the entire remaining column height.
- Removed all console calls and the periodic diagnostic formatting block from the silent-aim callback. Atomic status and counts remain available in the dashboard without console output.
- Both active aim paths use one shared controller/pawn enumeration per evaluation. Previously they scanned once for the local index and again for targets. Preserve generated field offsets and full handle-serial validation; no speculative offset substitution. The dashboard distinguishes occupied controller slots from resolved pawn handles.

Validation: feature regression tests exercise the production normal/silent paths, controller slot 64, stale handles, and chunk boundaries. The production menu renders all 12 pages across multiple frames in an isolated ImGui context. `tests/imgui_preview.h` produces offline BMP previews from actual ImGui draw data for visual inspection. No game input or injection is performed by these tests.

Live entity layouts and the reported frame-time impact are not established by synthetic tests. Dashboard counters reflect the last aim evaluation; they may remain unchanged while aiming is disabled or menu input is blocked. Existing placeholder features/profile actions remain placeholders.

Subtick diagnostics: the current hook calls RunSilentAimSubTick on the original DWORD source before engine serialization, keeps the three float angle writes, and verifies their history copy afterward. The function reads all seven source DWORDs once and bit-copies slots 4-6 into pitch/yaw/roll; nonfinite input is rejected. The Aimbot page's expandable Subtick angle debug panel samples at most four times per second without console logging. It shows the source address/raw angle bits, input/output angles, eye/target XYZ, and selected target name/health/team. Name reads occur only for a published sample. Invalid input or no target produces an empty target sample; opening the menu retains the last callback sample. Tests cover float decoding, unchanged tick fields, invalid values, selected controller name and pawn health/team, and stale debug-data clearing.
